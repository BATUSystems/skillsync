# Lessons from practice → rules

Read in a dispute about order, leases, push or status; the table maps events to rules.

| # | Event | Rule (where) |
|---|---|---|
| 1 | assignment to a busy card (names got shuffled, duplicates) | aliases from the names list + a probe before every assignment (Start 3–4, Assignment) |
| 2 | a "waiting" ghost session blocked a package for 2 h | no answer to the probe → unavailable, reallocation, request for a restart (Start 4) |
| 3 | a push of documents broke another card's fast-forward | PUSH SLOT for all pushes to the base, documents too (`direct` mode; in `pr` dispatcher documents stay off the base; loop) |
| 4 | "SEC-33" twice for different gaps | IDs only from the dispatcher, working labels to be replaced (loop, `ID REQUEST`) |
| 5 | three branches with EF migrations | the later integrator regenerates the migration after the rebase (`MASTER MOVED`, multi-session.md) |
| 6 | a reported push that did not happen | `git ls-remote` — hash verification (`PUSHED`) |
| 7 | a "known old failure" without evidence = a data dependency | evidence from a clean master required; otherwise it belongs to the package (Boundaries, multi-session.md) |
| 8 | load with 3 cards → unstable tests | `max_load`/disk guards, recommendation of 2 cards for E2E (Start 5, Assignment) |
| 9 | a fixed date in a test turned master red for everyone | `MASTER RED` + one owner of the fix, the rest do not fix (loop) |
| 10 | user GO in the cards against draining | a decision in the card takes precedence; update the state (Boundaries) |
| 11 | a project after an iteration without `docs/lessons`, because assignments required only `docs/domain` | every `ASSIGN` explicitly requires: rules → `docs/domain`, confirmed failures → `docs/lessons` (Assignment) |
| 12 | the dispatcher counted the chain `zsh -c` → `timeout` → pytest as three runs | count only `python -m pytest` processes by cwd (skill `agent-runtime-pitfalls`) |
| 13 | a machine restart would have interrupted a run lasting several hours | before the restart: commit WIP in all cards; wait for a finishing full run when it saves a repeat |
| 14 | a package with unquoted YAML in the docs header passed PUSH GRANT, `doctor` failed only on develop | before `PUSH GRANT` run `skillsync doctor` in the card's worktree; gate your own docs commit on the result (`grep -q PASS && git commit`), not on merely printing the status |
| 15 | `while pgrep -f "<pattern>"` loops in the cards spun for 6–8 h (matching their own shell) | at status time review the cards' processes by cwd and parent; point the owner to the PID to kill, wait only on a PID (`kill -0`) or a log marker |
| 17 | a card's subagent did `cd` into a nonexistent worktree, the chain went on and `git checkout -f --detach` hit the dispatcher's checkout; the dispatcher's docs commit landed on a foreign branch | cards: subagent git commands only as `git -C <path>` after checking the directory exists; the dispatcher gates its commit on `git symbolic-ref -q HEAD` = the main branch (next to `doctor`) |
| 16 | a "BE only" package added an enum value; the FE i18n dictionary guard failed only in the next FE package | FE guards reading BE code (dictionaries, error codes) are mandatory before `PUSH GRANT` of every package that changes enums, dictionaries or error codes — even without FE changes; put it in `ASSIGN` |
| 18 | the ASSIGN of the spec stage ordered the plan loop before "GO plan"; `plan-review` PASS (attempt 5) before `go-plan` was invalid, attempt 6 was needed (P2a-spec-d1, run `okno-sesji-podumysly-zalaczniki`) | ASSIGN of the spec stage in the order: `spec` loop → "GO plan" → `plan` loop from round 1 → "GO implement"; do not order a plan review before "GO plan" (rule: `feature/references/spec.md`, resume table, rows `approved`/`draft (waiting for spec)` and `approved with Spec-sha`; order: `review-loop.md`) |
| 19 | a card recorded the review rounds as separate steps `review-1`/`review-2` (`review-1` stayed at `FAIL` → `incomplete`, `REPORT REJECTED`); on the repeated closing a repeated `final` without a cause gave `unexplained`, only `final` with `--cause` gave `recovery` (P1-enoent) | subsequent rounds in the same step with a growing `--attempt`; a repeated closing as `final-2` or a repeated `final` with `--cause` — on a rejection put this in the correction request (rule: `feature/references/measurement.md`, section on steps and closing) |
| 20 | corrections appended evidence to a log file that an earlier record already pointed to (P1: `K1-mutation.log`, P2: reports `1-implementer.md`, `3-test-writer.md`) — the retro has a permanent `partial` evidence rubric, acceptance only by a decision (D6) | every attempt and correction writes the evidence to a new file `<step>-<attempt>.log`; put this in `ASSIGN` and in the correction assignment; changed evidence is not repaired by a new record (`feature/references/measurement.md`, `--evidence`) |
| 21 | a Skillsync worktree with a copy of `.github/.skillsync.yaml` lay in `discover_paths`: watch generated `CLAUDE.md`/`AGENTS.md`/`.claude` in it, and `doctor` differed from the baseline (P2); the P3b demo had to be moved outside `~/Repos/BATUSystems` (D12) | keep demos and worktrees outside `discover_paths` or without a manifest; when a manifest is needed (worker-mode, checkpoints), expect files generated by watch, compare `doctor` in the same worktree and after removing the worktree check the watch journal |
| 22 | a card gave hours in `STATUS` from memory and from an estimate ("around 09:50"), the station clock showed more than an hour later; the dispatcher recorded them in the state | the first line of the report `date: <date output>`, hours in the body only from logs or from `date` ([multi-session](../../feature/references/multi-session.md#verification-and-reports), loop) |
