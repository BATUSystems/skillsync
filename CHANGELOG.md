# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

The generator version (`skillsync --version`) and the version of the core layer (`layer.yaml` in `library/`)
are separate numbers. When they do not match, `skillsync doctor` reports a warning.
What counts as MAJOR, MINOR and PATCH: [docs/upgrading.md](docs/upgrading.md).

Every release has a **Breaking** section that lists incompatible changes. When a release has none, the section says "None."

## [Unreleased]

Upgrading from 1.21.0: [docs/upgrading.md](docs/upgrading.md), section "Przejście 1.21.0 → 2.0.0".

### Breaking

- **Consents from the status page need a signed-in session with the new role `approver`.** The approval token (`X-Approve-Token`, `#zgoda=` in the address, `tokenId` in `/healthz`) and the default approval port 5141 are gone: the page has one default socket (5140), and `GO plan`, `GO implement`, `CP` and `READY` are `POST`s of the session of an `approver` account (session, CSRF and exact `Origin`; local access or TLS), without a second password. Clients that sent the token are refused.
- **A `CP` or `READY` from the status page pushes exactly the shown commit** (core skill `feature`): a dirty tree or another HEAD is a question, not a new commit. Where the question where to hand over would be asked (`direct`, no plan line `Oddanie:`, a base other than the working branch), the shown `target` of such a `CP` answers it: the agent does not ask, writes the line after the push (writing it first would dirty the tree) and commits it locally without a push (`specs.tracked: false`: repeats the snapshot).
- **`CP` and `READY` requests carry the shown `branch`, `target`, `mode` and `base`** (a difference is refused with 409 `delivery_changed`, a missing field with 400), and a server with more than one worktree tab refuses a consent without `tab` (400).
- **Rule of consents in the core instructions and skills:** a consent may also come from an `approvals.jsonl` entry with `source: dashboard` of the plan's run and a sha equal to the current one (`CP`/`READY` used once, with the shown branch and target); `by`, `role` and `session` are an audit trail, not a verification. Run `skillsync link` in the projects.
- **`dashboard serve --allow-proxy-headers` no longer starts** (BLOCKED with a hint): proxy headers decide whether a request counts as local, so a proxy must be declared with `--trust-proxy` and `--proxy-address`. `--trust-proxy` without a proxy list refuses to start (also in `prototype serve`).
- **The renderer of the status page no longer reads `deps.hasApproveToken` or `approvals.tokenRequired`.** A host that gives consents passes `deps.session()` (see the dashboard contract); a host without it behaves as before and `actions.approve` also receives `branch`, `target`, `mode` and `base`.
- **Sessions of the prototype and status server:** the cookie name now contains the origin type and the server id and is `SameSite=Strict` (every user signs in again); changing a password ends all sessions of the account; sessions from `login-link` never carry the roles `approver`, `acceptor` or `developer`; over plain HTTP from the network nobody signs in by default, and `--allow-plain-login` admits only accounts whose roles are `commenter` and/or `expert` (see the next point).
- **Plain HTTP from the network is refused for logins, password changes and consents.** A password is accepted only from the loopback (no proxy header, a loopback `Host`) or through TLS: a request from a trusted proxy (`--trust-proxy` with `--proxy-address`) that sends `X-Forwarded-Proto: https`. `--secure-cookies` only marks the cookie `Secure` and does not make a request secure. A refused login gets 403 `secure_connection_required`. `--allow-plain-login` admits plain-HTTP sign-in only for accounts whose roles are `commenter` and/or `expert`, never `acceptor`, `developer` or `approver`. A proxy must send `X-Forwarded-For` and `X-Forwarded-Proto`: a proxy on the same machine that adds neither and sets `Host` to a loopback address looks like a local connection. Consents from another machine need TLS; `--allow-remote-approvals` lifts only the consent-context check and does not let an `approver` sign in over plain HTTP.
- **Accounts with the role `approver`** need a password of at least 14 characters typed at a terminal (`--password-prompt`) in every command that sets it, and sign in only on the status-page origin (not in `prototype serve` or the standalone file).
- **"Abandoned" plans have a new definition and an action.** `approved`, no checked Progress step, no local run of its `Przebieg:` line and no change for more than 14 days (git commit date; file time for uncommitted or untracked files). In `GET /api/history` such a row has `abandoned: true` and `action: abandon` (a new value of `action`), rows get the field `restoreTo`, and `plan unarchive` of a plan with the `Porzucony:`/`Abandoned:` line returns it to `approved`, not `done`. A host that renders History must know the new action (treat an unknown one as no action).
- **`dashboard serve --approve-bind` and `--approve-host` without a port are BLOCKED** (exit 2, with a hint): consents share the page socket, so there is no consent socket to bind or to name. `--read-bind` and `--read-host` still apply to the page socket.
- **A `delivery` operation parameter named `pat` or `pwd` (also as a part of a name, `github_pat`, or in camelCase, `githubPat`) is refused**, like `token` and `password` already were: credentials come from the environment.
- **`dashboard serve --prototype-port` is now the port of the second origin of the server**, not the port of a separate `prototype serve` that the page checks: forbidden ports (4444–4448, 9222, 9333) and 5141 are refused (BLOCKED), and `prototype.port` of the manifest no longer decides it for the start directory (default: page port + 2).
- **The prototypes left the "Questions" tab and the status field `expertQuestions.current.prototypes` is gone** (`current` is `{spec, open, blocking, items}` and `null` without a question of the run); every prototype is in `prototypes[]`. The renderer replaces the link "Prototype · N/M" beside the tabs with the tab "Prototypes", and the key `P` opens it (the progress tab keeps `P` only without prototypes).
- **A reader without a session gets a redacted view** of the status page, including `/api/status`: pseudonyms instead of logins and addresses, names instead of absolute paths (`project.path`; every other absolute path in a composed field keeps the name of its last part only, also outside the project and the home directory); a script that read them anonymously must sign in or use `skillsync dashboard show` on the machine.
- **The prototype server refuses service worker requests** (403 `service_worker_refused`), also in `prototype serve`: a prototype that registers a service worker no longer gets it.
- **The comments and question API of the prototype origin listen where the status page listens.** By default that is every interface (page port plus 2), so anonymous readers on the network get the redacted comments. To keep it on this machine use `--read-bind 127.0.0.1` (it moves the page and the prototype origin together) or `--local-only`. `--no-approvals` covers consents only; comments by a signed-in account are not blocked by it.
- **`dashboard serve --read-host '*'` without `--read-port` is refused (BLOCKED).** The default mode has one socket that also carries the consent page, which always checks the `Host` header.
- **`prototype user add` refuses with `account_required`** when the pseudonym derived from the address (the part before `@`) is already used by another account; pass `--account`. An explicit `--account` that is taken gives `account_taken`.

### Added

- **Banner about failed sign-ins on `approver` accounts:** the status page shows a signed-in approver the latest series of failed sign-ins of each such account (account pseudonym, count within 15 minutes, time). The data is `server.alerts` of `GET /_api/v1/session` and the optional `alerts` of `deps.session()`; a host without the field draws the page as before.
- **Prototype origin on the status-page server.** `dashboard serve` serves the prototypes from a second socket (page port + 2, `--prototype-port`, `--prototype-url`; 5141 is refused), with its own `Host` list and 403 `service_worker_refused` for service worker requests (also in `prototype serve`); `--single-origin` keeps one origin at the price of isolation and of consents.
- **Actions on prototypes from the status-page origin:** `POST /api/prototypes/<slug>/accept|unaccept|restore|resolve|delete` and `POST /api/project/accept` for a signed-in account, by the role matrix of the engine, audited; refusals are `{error, code}` (for example 409 `prototypes_not_served`).
- **`dashboard serve --detach` and `dashboard stop`.** `--detach` runs the server in the background (a log file in the machine state directory), waits until the page answers and prints its address; `dashboard stop` is `servers stop` limited to status page servers, for the directory and the main checkout of the project, with the same output and exit codes.
- **Closure line in the plan (`Zamknięcie: final <date> <sha40>`, alias `Closure:`).** `checkpoint --final` writes or refreshes it under the `Przebieg:`/`Run:` line of the one plan of the run (result field `planClosure`; a problem is only a `plan-closure:` warning, the exit code does not change). A `done` plan with a valid line is closed for the Stop hook, `doctor` and `status` in every checkout, without `.skillsync/runs`. The line is read only in the plan header, outside code blocks.
- **`skillsync status` fields `plans[].closure`** (`{state, sha}` for `done` plans: `none`, `tracked`, `final`, `bad-line`, `foreign`, `open`) **and `plans[].abandoned`** (`approved` plans); a finding reminds to set `Status: done` for a plan with the line and every step checked. `doctor` warns about a malformed closure line and about an `in_progress` plan that has one.
- **`skillsync plan abandon`** and the "Abandon" button in the History tab (with a confirmation and an audit row): an abandoned `approved` plan becomes `archived` and gets the line `Porzucony: <date>`.
- **Role `approver`, account pseudonyms and session rules:** optional unique field `account` in `users.json`; approver sessions end after 2 h of inactivity and at most 12 h; limiters answer 429 with `Retry-After` per account and source, parallel password checks are capped (503).
- **Sign-in on the status-page origin** (`/_login`, `/_api/v1/session|login|logout|password`) and a one-time hand-over of the session to the prototype origin (`/_handoff/begin`, `/_handoff`), bound to a nonce cookie of the prototype origin.
- **New flags of `dashboard serve`:** `--allow-remote-approvals` (consents from another machine without TLS, trusted networks only), `--allow-plain-login`, `--local-only`, `--trust-proxy` with `--proxy-address` (trusted proxies, list required), `--secure-cookies`, `--public-url` and `--prototype-url`.
- **The status page works with the session of its origin:** the account, "Sign in", "Sign out" and "Change password" in the header, a bar that says why a consent cannot be given, a confirmation window for `GO plan`, `GO implement`, `CP` and `READY` (word, document, tab, short sha, branch, target or PR base, mode; no password) that closes without sending when what it shows changes, and the History buttons "Abandon", "Archive" and "Restore" for an `approver`. The page removes old `#zgoda=` addresses from the address bar and old stored tokens from the browser. `server` of `/_api/v1/session` on the page gains `passwordMin` and `passwordSignIn` for the own account, and the `by` of `plan-status.jsonl` rows is the account of the session.
- **Tab "Prototypes" of the status page:** every prototype with its title, iteration, accepted and stale screens, writing marker, open threads, comments after acceptance and plan gate (`prototypes[].title`, `prototypes[].gate`), readable without signing in; "Open" in a new tab (`noopener noreferrer`) or in a sandboxed frame (no consent buttons while it is on the screen); for a signed-in account a view without a frame with accept, withdraw, restore, resolve, delete and project acceptance, each behind a confirmation window that sends exactly the hashes and the version shown; "Sign in to the prototypes" (one-time handover). New reads `GET /api/prototypes[/<slug>]` (signed-in only); `/api/status` gains `prototype.url`, `prototype.served`, `prototype.frame` and `singleOrigin`. The header names the handover consent of the delivery mode, and `--single-origin` explains why consents are off. Optional renderer deps: `prototypeFrame`, `actions.loadPrototype`, `actions.prototypeAction`.
- **`dashboard serve` says who holds a taken prototype port:** a start that moves the prototype origin off page port + 2 names the owner (the project and the socket, also a prototype origin of another status page server), as does a refused `--prototype-port` or page port; the state file of a server gains `prototypePort`.
- **`prototype serve` names `dashboard serve`** at start (not with `--demo`).
- **Consent audit:** consents are written to `run/audit.jsonl` (account, source, word, path, sha) as `consent_intent` right before the write and `consent` only after a write that happened, refusals as `consent_refused`; a consent whose `consent_intent` line cannot be written is not recorded (503 `audit_unavailable`). Rows of `approvals.jsonl` gain `by`, `role` and `session`; anonymous readers of `/api/status` see only `word`, `at`, `sha`, `source`, `target` and `planState`.
- **The tab "Tests" warns a reader without a session** that the results are raw (`tests.publicRaw`; not with `tests.mask: on`).

### Changed

- **The windows of a decision on the status page** (consent, password, feedback, action on a prototype, History) are `<dialog>` windows in the top layer of the browser; a host without `showModal` keeps them as before.
- **`dashboard.approve_bind` in the default mode prints a warning** with the way out (`read_bind`, `--read-bind` or `--approve-port`) instead of being ignored silently; `local_only` prints none.
- **Texts after the token and the two ports:** the tip of an inactive consent button names the `approver` account and local access or TLS (not `--approve-host`), the hint about consents from a phone no longer offers `--allow-remote-approvals`, and the help of `--prototype-port`, `--approve-bind` and `--allow-remote-approvals` states the real rules.
- **The git facts of `GET /api/history` are kept** (at most 60 s) while the plans and the repository do not change, so repeated anonymous reads start no git process.
- **A reader without a session sees a redacted view** on the status page and the prototype origin: pseudonyms instead of logins and addresses, names instead of absolute paths; documents and test results stay open; `prototype serve` is unchanged in this respect.
- **One closure rule for the Stop hook, `doctor` and `status`.** The `open` message of the Stop hook warns not to record `final` for a run of another session or machine (ask the owner or archive the plan); an `in_progress` plan with every step checked and a valid closure line no longer blocks the turn. `Przebieg:`/`Run:` lines inside code blocks are not read.
- **Run `skillsync link`** in the projects to refresh the copy of `check-closure.py` (symlink mode refreshes it by itself).
- **Masking knows the short names `pat` and `pwd` everywhere.** Text pairs (`pat=`, `;Pwd=`, `"pat":`, `DB_PWD:`), the keys of `delivery` and `e2e` reports and the flags of a recorded test command (`--github-pat VALUE`). `PWD=/path` (the working directory), `PATH`, `compat` and `--pattern` stay readable; a bare `pwd:` or `PAT:` is prose and is not masked.
- **One definition of the secret words** (`secret_words.py`) for the masks and for the secret scans of `feedback` and `prototype question`; the URL parameters in messages about layers mask `pat`, `pwd`, `secret`, `client_secret`, `api_key`, `sig` and the like too, not only `token`, `password`, `pass`, `auth` and `key`.

### Fixed

- **A server listening on `::` also answers on 127.0.0.1 on Windows** (the socket asks for both protocols): the printed local addresses refused every connection and `dashboard serve --detach` timed out.
- **`dashboard serve --single-origin` records and undoes no screen acceptance on any route.** A prototype script runs there on the origin of the session and could accept screens as a signed-in acceptor or developer through `/_api/v1/…`; accept, unaccept, restore and project accept now answer 403 `approvals_disabled` (comments still work).
- **A listening address that is not the loopback no longer leaves this machine without a way to sign in.** With `--read-bind`, `dashboard.read_bind`, `--approve-bind` or `--port N --host` on such an address (also another one of `127.*`) the page and the prototype origin listen on `127.0.0.1` as well, on the same port; the start prints both addresses, and the address named by `url`, `--detach` and the console answers. A port taken on `127.0.0.1` blocks the start.
- **With `workflow.specs.tracked: false` the dates of the plans no longer come from git history:** `status`, the History tab and `plan abandon` do not ask `git log` about `docs/plans`; a plan is dated by its file.
- **Consent audit folding:** refused requests that differ only in an unknown `tab` or in the slug of a prototype action are folded into one line a second, as equal refusals are.
- **No endless redirect behind a proxy that rewrites `Host`** without forwarding headers: the redirect to the origin of `--public-url`/`--prototype-url` sets a 30 s marker cookie, and a request that carries it is answered.
- **A running 1.x status page server of a project is recognised as an old one:** `dashboard serve` (also `--detach`) no longer adds a tab to it and is BLOCKED `legacy_server`.
- **A consent that waits for a file lock is checked again under that lock** (a logout, an expired session or a lost role during the wait writes nothing), a consent whose body ends before its `Content-Length` is refused (400 `badLength`), and a partly written row of `approvals.jsonl` or `plan-status.jsonl` is finished or removed.
- **The command that `dashboard serve` names for making the first approver parses** (project path, e-mail, `--password-prompt`, `--confirm-mixed-fleet`).
- **A question resolved in a table of the open questions section is no longer shown as blocking** on the status page and in `blockingQuestions`, when its row says so explicitly: a cell that begins with `[ROZSTRZYGNIĘTE …]`/`[RESOLVED …]` or a `Status` value of exactly `rozstrzygnięte`/`resolved`; a filled answer column alone resolves nothing, and in doubt the question stays blocking.
- **Behind a trusted proxy the sign-in limits read every `X-Forwarded-For` line**; only the first one was read, so a client sending a line of its own could choose the source it was counted as.
- **The body of a sign-in request has one time limit** (10 s, 408 `body_timeout`); a client sending a byte at a time kept a worker busy without end.
- **`run/audit.jsonl` no longer grows without end:** at 5 MiB it is set aside as `audit.jsonl.1` and four older files are kept.
- **Windows: a server started with `dashboard serve --detach` no longer ends when the SSH session or terminal that started it closes** (it leaves the job object of the terminal; when that is not allowed, the command warns). The `log` field of its JSON report uses `/` like the other paths.
- **`servers list` and `servers stop` no longer see a second "prototype" server in a status page with accounts:** `dashboard serve` writes the file of `login-link` (its own process), which was listed as a prototype server and refused by `servers stop` (exit 2) although the page had stopped.
- **`servers stop` of a status page server with two sockets** (`--read-port`, `--approve-port`) sends one signal to the process and reports both sockets with the same outcome; the second socket was signalled again or reported `refused` (exit 2) although the server had stopped.
- **`servers list` and `servers stop` recognise that a 2.0.0 status page server accepts consents** (its state file holds no token), so the warning about a waiting consent is printed again.
- **An unterminated quoted secret that ends in a backslash is masked.** `password="abc\` just before the end of a line was printed unmasked.
- **`…_PAT_RO`, `…_PWD_PROD` and camelCase names (`githubPat`, `dbPwd`) are masked in text.** On Windows `os.environ` gives variable names in upper case, so an environment variable with a camelCase name is not recognised as a secret there.
- **Fewer false alarms:** `OLD_PWD`, `OLDPWD` and `INIT_PWD` with a path, the flag `--pwd <path>` and code such as `url_pat = re.compile(…)` stay readable and no longer stop `feedback send`.
- **The secret scans stay fast on a very long word.** The scan of `prototype question`, the gate of `feedback send` and the mask of URLs in messages about layers took tens of seconds or more on a word of 40–100 thousand characters, and so did the mask of URL credentials in reports on a long run of `a:` (a way to stall a server with crafted text); they are now linear, with the same answers.

### Security

- **With `--single-origin` the writing marker cannot be lifted over HTTP** (403 `approvals_disabled`): a script of a prototype could remove it and the gate would pass on the earlier acceptances.
- **A reader without a session gets only the main keys on a list** from `/api/status`, `/api/tabs` and `/api/history` (of the answer and of every row of their lists of tabs and of plans): a new key is not public until it is added there, and a test pins the whole tree of keys of those answers. A signed-in session sees what it saw.
- **The prototype origin no longer serves spares and copies of files to a reader without a session** (`*.bak`, `*.orig`, `*.old`, `*~`, `*.json-old` and the like, wherever they lie; copies of `prototype.json`; a `prototype.json` anywhere but in a prototype or in a frozen iteration).
- **The link to the session of the agent (`--session-url`, `session.url`) is given only to a signed-in reader**; for everybody else it is `null`.
- **Absolute paths are hidden from a reader without a session** in the fields the server composes (status, tabs, History, tests, also the command line of a test run). A path under a working copy of the project or under the home directory is always replaced. Another absolute path is shortened to its last name by a heuristic on text: one glued after a letter, a digit or `_` (and, for a POSIX path, after `-`, `.`, `~`, `…`, `}`, `)`, `]`, `%`, `*`, `#` or `$`) reads like a relative path and stays as written. Test results and documents stay open.
- **The CSP of the status page has no `'unsafe-inline'` in `style-src`;** the style blocks of the sign-in page and of the server's banners are allowed by their hashes.
- **Text of a document can no longer write HTML on the status page.** Two ways led from the content of a plan, a checkpoint or a question to markup of its own, for example a link with a `style` that covered the page and its consent buttons (scripts stayed blocked by the CSP): a link nested inside an autolink or inside another link target put the HTML of the inner link into an attribute, and the mask of secrets run over the finished HTML took a quote and a closing tag with the value after `token=` or `password:`. A link target no longer takes `<`, `>`, square brackets or an already rendered fragment, and every mask now changes only the texts and attribute values of the HTML, never the markup; a secret that formatting splits turns the block it is in into plain masked text (also a word such as `password`: followed by a description). Both are also in the 1.20.x and 1.21.0 releases (checked on 1.20.1 for the renderer); the fix ships in 2.0.0 only.
- **The e-mail and path mask of the page without a session also holds for the formatted fields.** An address split by Markdown (bold, code, a link, a backslash or an invisible character, also in the domain) or written in a link target stayed readable in `titleHtml`, `textHtml` and in the plain text beside them. Nothing is substituted inside HTML any more: a reader without a session gets a formatted field only when the mask changes neither its source text nor the text it shows, otherwise the field is left out (also all of a `## Wynik` with one address or absolute path) and the page shows the masked plain text. A heading id now comes from the words the heading shows. The mask of the page without a session is new in 2.0.0.
- **A guard looks at all rendered HTML before it leaves the status server** (also `/api/doc`, also for a signed-in account): only the tags and attributes of the renderers, links to http(s), mailto or the page itself, no `<`, quote or NUL in a value. A field that fails is not repaired: it gives way to the plain text, and a document becomes its escaped text. A link whose target holds a quote is now shown as text.
- **A hostile document no longer stops the status server.** Deeply nested quotes or lists crashed the renderer (`RecursionError`: no status, no document, no consents), and some patterns took from seconds to minutes on a few thousand characters while holding the interpreter. Nesting stops at 8 levels, and the patterns of the renderer, of the address mask and of the plan and checkpoint readers that backtracked on long runs of spaces or letters are linear. As a side effect a link whose label or target holds square brackets, and a code span closed by a run of backticks of another length, are shown as text. The 1.20.x and 1.21.0 releases have the crash and the slow patterns of the renderer; the fix ships in 2.0.0 only.
- **An account with `approver` changes its password only on the page of the status board:** a session of a login link on `prototype serve`, the standalone server or `--single-origin` no longer accepts it (403 `approver_login_elsewhere`, audited as `password_refused`; the role is also checked under the lock of the users file). `server.passwordChange: false` of `/_api/v1/session` says so, and the login page and the prototype engine show a message that can be closed instead of the form (run `skillsync prototype migrate` for existing prototypes).
- **A one-time hand-over of an `approver` session to the prototype origin no longer extends its inactivity limit** (2 h). The activity of an `approver` session is a write with a valid CSRF token on the origin of the status page; the hand-over and writes on the prototype origin do not extend it, and the cookie handed over there lives no longer than what is left of that session.
- **A right password where the account cannot sign in counts as an attempt.** For an `approver` outside the origin of the status page, and, with `--allow-plain-login`, for accounts that flag does not admit over plain HTTP, a right password no longer clears the failed-attempt count: it is counted like a wrong one, stops at the same limit (429) and raises the `approver` alert. The answers stay different (403 with the way to sign in for a right password, 401 for a wrong one or an unknown address), so within the limit such a channel still tells a right password from a wrong one.
- **A trusted proxy that does not send `X-Forwarded-Proto: https` is plain HTTP.** The last value of that header counts (the one the proxy added); see the Breaking note on plain HTTP.
- **The window of a consent shows what it asks for.** Control, bidirectional and other invisible characters are shown as their codes; the window belongs to the account and roles that opened it and closes when they change; the second click of a double click confirms nothing (also in the window of a prototype action and in History); a branch name with a hidden character, which git accepts, is not offered or recorded for a consent. The window that deletes a thread says how many messages go with it.

## [1.20.1] - 2026-11-27

Upgrading from 1.20.0: [docs/upgrading.md](docs/upgrading.md), section "Przejście 1.20.0 → 1.20.1".

### Breaking

None.

### Fixed

- **`skillsync servers stop` of a status page server with two sockets** (the default of `dashboard serve`, also `--read-port` with `--approve-port`). The server has two state files and was handled twice: it got a second signal, and when the process had already ended the second socket was reported `refused` with exit code 2 although the server had stopped (on Windows, by the code, every time; on Linux and macOS a race). Now the process gets one signal and both sockets report the same outcome. Covered by tests with a fake system (also a variant that behaves like Windows) and reproduced on Linux with a real two-socket server; not run on Windows.

The band and ring are rectangles, so a rounded control with a border (straight sides under half of the perimeter, such as a round radio) that does not pass is UNVERIFIED `shape-unknown` instead of FAIL; a really pale round border is therefore UNVERIFIED too. ### Security

- **`ui-verify`: the PNG decoder refuses decompression bombs before decoding.** `decodePng` walks the chunk headers (no decoding) and refuses, with `ImageLimitError` and exit code 2: a buffer over 64 MiB, a first chunk that is not an IHDR of length 13, a second IHDR (`pngjs` takes the last one), a zero dimension, more than 16384 px per side or 50 M px, an interlaced (Adam7) PNG, which `pngjs` inflates without any bound, and an oversized (over 768 bytes), malformed or repeated PLTE chunk (`pngjs` adds an array per palette entry with no limit, so a file under 64 MiB could demand gigabytes of heap). `pixel-diff` and `diff` check that the path is a regular file within the size limit before reading it, so a huge file or a link to `/dev/zero` is never loaded, and more than 100000 chunks are refused too (`pngjs` keeps an object per IDAT and pays CPU per chunk). `pixel-diff`, `diff`, `measure`, `capture` and `a11y` all decode through it; `diff` reports it as a read error (exit 2, not UNVERIFIED). What the walk does not refuse reaches `pngjs` as it is: buffers without a PNG signature, truncated files and bytes after IEND. `pngjs` 7.0.0 (pinned) gets no data from them and fails before allocating; a test on the real `pngjs` (valid CRCs, so it reaches the property under test) keeps that assumption honest.
- **`ui-verify capture --allow-trace`: owner-only artifacts, a `.gitignore`, and an honest warning.** `trace.zip` and `storageState.json` are written with mode 0600 (POSIX; an existing file is `chmod`ed before the new content is written), `capture` creates `<outDir>/.gitignore` listing both files only when none exists (never in the configuration directory itself, never over an existing file or symlink), and the stderr warning now names what they can hold (form field values and passwords, headers and bodies, cookies and tokens, DOM snapshots, screen frames), says the output mask does not cover them and that the absence of a known secret proves nothing. Binaries are still not masked: `trace.zip` and PNG are written as bytes, and `storageState.json` goes through the text mask for known secret values only. This is a documented boundary, not a guarantee.

### Fixed

- **Run files with an unknown owner are read, not refused.** A checkpoint record whose `owner` is a name this version does not know (written by a newer generator, e.g. a later owner of a fix) no longer makes the whole run file unreadable: the record is kept, the owner is skipped in `retro` candidates and a warning goes to stderr once per owner. Writing a checkpoint and `retro-decide --owner` stay strict (only the owners of this version); a malformed owner value is still an error (the name must look like `[a-z][a-z0-9-]{0,31}`, and a record with an owner still needs its `cause_key`). A candidate whose records name an unknown owner next to a known one has no single owner (`needs_owner`).
- **Prototype gate: a mistyped English bypass line no longer passes silently (fail-open fixed).** Before, a mistyped `Prototype gate: skipped` line passed silently as `PASS`. - **The one-time `precmd` hook of the zsh completion block no longer ends the shell when `compinit` fails.** The line `(( $+functions[compdef] )) || { autoload -Uz compinit && compinit -i; }` returned the status of the failed `compinit`; with `setopt ERR_EXIT` in the user's `.zshrc` that closed the interactive shell at the first prompt, and with `ERR_RETURN` the hook returned before it registered anything or removed its function. The line now ends with `|| :`, so the hook goes on and, when `compdef` is still missing, prints its one-line warning. Run `skillsync completion install` again to refresh the block in `.zshrc`.
- **`checkpoint --final` no longer repeats `retro-quality-missing` after a late retrospective.** The warning judged the retrospective against the earliest `final` of the run, so a run closed once without a `retro-quality` PASS, then given one and closed again (`final-2`, as `retro-quality.md` instructs), kept the warning for ever and the audit trail would have had to be rewritten. ### Breaking

- **`test-run` blocks a clean exit code when the output reports failed tests of Playwright, Vitest or Jest (source `regex`).** When the command exits 0 and the counters come from the output itself (no adapter and no JUnit report, `source: regex`), an anchored summary of failed tests makes the run `BLOCKED` with exit code 2: `  N failed` or `  N interrupted` (Playwright), the `Tests` line with `N failed` and not `Test Files` (Vitest), `Tests: N failed,` (Jest). Before, such a run was `PASS` or `BLOCKED` for another reason. The Jest pattern has no end anchor, so a log line that starts with `Tests: 2 failed, …` also blocks. The sources `junit` and `adapter` are unchanged, and the bare `N failed` text (`3 failed attempts`, `0 failed`, `failed=0`) still does not block. No flag lifts it: `--allow-no-count` does not. Workaround: fix the command or the wrapper so that its exit code is the exit code of the tests; pass `--format playwright` or `--format vitest`, or a JUnit report with `--junit` (Jest has no adapter, so use `--junit`).

## [1.4.1] - 2026-11-15

### Fixed

- Layer rules, the config and the dangling-link check on Windows with Python 3.13+: a path rooted with `/` or `\` but without a drive (`/a/**` in `layer_rules`, a `/a/b` source or a link target) is absolute again, as it was up to Python 3.12 (`ntpath.isabs('/x')` became False in 3.13). `fsutil.isabs` names the meaning; `layers.path_matches('/a/b/c', '/a/**')` matched nothing on 3.13, `layers` stored `/a/b` as `C:\a\b`, and `link` took a rooted link target for a relative one. POSIX unchanged.
- `FileLock` on Windows: opening the lock file is retried briefly (at most 0.5 s and never beyond the lock timeout) when the system refuses it for an instant, because the holder
  that just released the lock is deleting the file (`unlink=True`, the approvals lock; `os.open` answered `PermissionError` EACCES). Before, parallel `approvals record` calls could
  sporadically end `BLOCKED` ("Permission denied: ...approvals.jsonl.lock"): measured 43 refusals in 24000 acquisitions by 6 processes, always at that `os.open`. A refusal that lasts
  (a real permission problem) is still raised after the short retry. Single use, the inode check after a delete and the release on process exit are unchanged.
- `leakguard`: a hook command line containing a path that starts with `/` is checked as an absolute path on Python 3.13+ on Windows too (`os.path.isabs('/x')` is False there since 3.13, so `hook_command_problems` skipped such a path and `hook-command-missing` did not report a missing file); POSIX unchanged.
- Prototype server on Windows: a refused open, rename or replace of a file that another thread has open or is replacing (`PermissionError`, WinError 5 or 32) is retried for up to half a second (`retry_transient`; other systems and other errors unchanged).
  Before, concurrent requests could fail sporadically: a one-time login link could be lost by every caller at once (nobody got the session, the token stayed valid), reading `questions.json` or `comments.json` during a write ended as a 500 `internal_error`,
  and a write could be refused while a reader had the file open. The single use of a login token is unchanged (the atomic rename decides, a missing source file means someone else won). Serving static prototype files and copying screens are not retried (no failure was observed there).
- Approvals file lock: `approvals.jsonl` is locked with a system lock (`flock`; `msvcrt.locking` on Windows), the same lock as the questions, comments and users files of the prototype server, instead of a `.lock` file that was created exclusively and taken over after 60 s. This fixes a race in which a late writer released the lock after its owner and left a stray `.lock` file (up to 60 s of `BLOCKED` for the next writers, and during the takeover the lock path briefly did not exist); in CI it failed this way in 7 of 157 completed macOS 3.12 jobs (about 4.5%) and in 1 of 157 3.11 jobs, 12-13 Nov. Ending the process releases the lock; a leftover `.lock` from an old write does not block; the `.lock` file is still temporary (removed under the lock, the next writer checks the inode). See docs/upgrading.md: after the update restart `dashboard serve` before the first approval.
- `QuestionsStore.sweep_orphan_lock` (removal of an orphaned `questions.json.lock`) removes the file while still holding the lock, and every `FileLock` checks after `flock` that the path still points at the locked inode (a waiting writer no longer ends up holding a lock on a deleted file).
- `FileLock`: a file system without lock support (ENOTSUP, EOPNOTSUPP, ENOSYS; ENOLCK after half of the wait) now gives `LockUnavailable` at once (503 `lock_unsupported`, a subclass of `LockTimeout`) instead of waiting for the timeout; other errors are still contention. Applies to the locks of expert questions, comments, users (also the `prototype user` commands) and approvals.
- `prototype serve` and `dashboard serve`: SIGINT (Ctrl+C) or SIGTERM right after the start, between installing the handler, announcing the address and `serve_forever`, ends the server cleanly (PASS, `stopped`) instead of a traceback and exit code -2; the handler is installed before the address is announced, and the start from installing the handler to `serve_forever` is under a `try`. In CI this failed once on macOS (a window of a few milliseconds).
- A symlink loop in a `discover_exclude` entry or in a project path is again treated as unresolvable (`common.discover_excludes`, `common.is_excluded`) on newer Pythons:
  `Path.resolve()` stopped raising on a loop in POSIX 3.13 and Windows 3.12, so the loop is now detected by a symlink that is left among the components of the resolved path.
- Prototype server and status page: a request that the server refused before reading its body (401, 403, 404, 405, 411, 413, a refused approval) could leave the declared body unread in the connection.
  On Windows the client then got a connection reset (WinError 10054) instead of the answer; on a kept-alive connection the leftover bytes were read as the start of the next request. Now a connection with an unread declared body
  is closed after the answer, with a lingering close (RFC 9112 section 9.6: the server half-closes, discards what the client still sends and then closes), bounded to 256 KiB and one second so that it cannot be used to hold a server thread.
  Requests whose body the handler read are not affected.
- `link` appends to a user's `.gitignore` (project root, `.github/`, `.claude/`, `.cursor/rules/`, the state folder) without rewriting it: the existing bytes and line endings (CRLF, LF or mixed) stay as they are and new lines follow the last line's ending. Before, the whole file was rewritten with LF, so a Windows project with `core.autocrlf=true` got a diff of the whole file instead of the added lines. The prototype ignore files (`.gitignore`, `.gitattributes`) use the same appending rule.
- `link` keeps the line endings and bytes of the user's `AGENTS.md`, `.codex/config.toml`, `.vscode/tasks.json`, `.claude/settings.json` and `.mcp.json`: the managed block or JSON is written in the file's own line ending (CRLF stays CRLF, a new file is LF) and the `*.skillsync-backup` copies are byte copies.
- `link` recognises a dangling library symlink written in the 8.3 short form (`RUNNER~1`) on Windows, so `link` after a skill rename removes the orphan.
- Run metadata (`runs`, the `benchmark` suite and fixtures) and `/proc` identity are read and written as UTF-8 explicitly (Windows used the code page).
- A path in run metadata that is rooted but not absolute on Windows (`/etc/hostname`, `\\x`, `C:x`) is refused as an evidence path or a benchmark fixture name on every system.
- `prototype question merge --driver` leaves a questions file with CRLF line endings byte for byte when the other side adds nothing (it rewrote the file with LF).
- Windows (Python 3.11 and 3.12): the test suite no longer fails for reasons of the platform that are not defects of the product. Tests were fixed (isolated
  `USERPROFILE`/`LOCALAPPDATA`, interpreter from `sys.executable`, quoted paths in YAML, a fake `az` and `git` that run on Windows, links with a relative target, `skillsync.exe` as the entry file, case-insensitive file
  trees); no test was removed or disabled, the simulated hosts that a real Windows file tree cannot show are skipped as subtests with a reason.
- `status plan approve`/`spec approve`: the warning about the pre-implement report no longer misreads a plan saved with CRLF line endings (the `Przebieg:` line was not found).
- `layers`: on a Windows host a backslash is a separator when paths are normalised and in `layer_rules` globs, whichever system is simulated.

### Changed

  `.claude/agents/Explore.md` after `skillsync link`.

- `skillsync spec approve` and `plan approve` drop the waiting note the approval satisfies (`(… czeka na … GO plan)` for a spec,
  `(czeka na GO implement)` for a plan) instead of leaving `approved (… czeka na „GO plan”)`; other notes such as
  `czeka na spec` or `szkic` stay, as the resume table decides on them.
- Prototype threads panel: a long handle label on a thread card now wraps within the panel (the button's `nowrap`
  used to widen the panel horizontally and clip the screen heading); the group heading has the same edge spacing as the cards.

## [1.0.1] - 2026-11-09

### Added
None.

### Changed

- Leak guard: with `authors_scope: committer`, a commit authored by the local user but committed by someone else (cherry-pick, rebase, merge button) has its author checked against `authors`; the foreign committer stays a notice (`foreign-commit`).
- `layers check --isolation` looks for identity files in the library directory of a layer (`layer.yaml` root, e.g. `library/`), not in the whole clone, so examples under `docs/` of the core clone no longer raise `isolation-foreign-identity`.

### Breaking

- Leak guard: code files (`*.py`, `*.ts`, `*.js`, `*.mjs`, `*.cjs`, `*.ps1`, `*.sh`, `skillsync`, `skillsync-ctl`) outside `tests/**` and `.github/**` are in the path class `instrukcje`, also under `docs/` and in the root; before they were attributions, so an owner nick in a code docstring passed. Now it is `FAIL` in core and org targets (the owner's real name stays allowed in org), allowed in personal. File names and suffixes are compared case-insensitively. `path_class_rules` in `leakcheck --json` and `leakguard patterns --json` has a new key `code`, and `atrybucje` no longer has `suffixes` or `exact_names`; patterns and `allow` entries with `path_classes: [atrybucje]` no longer cover code files. Shipped in a PATCH release on purpose: it closes a leak gap in the leak guard released the day before, and the only consumers of the `path_class_rules` schema are the core and our own layers (D297).

### Fixed
- Windows: paths in JSON output use `/` (`status --json` plans and `plan` results, run evidence, delivery logs, e2e observation, `skills list` references).
- Windows: `redact` applies the environment-secret substitution to dict keys only for secrets of 8+ characters, so a short secret value (`root` on the Windows runner) cannot rename structural keys such as `root` or `composed_root` in JSON reports; values keep the 4+ character rule (the `delivery` report scrubber follows the same key rule).
- Prototype, mobile view: loading a view iframe no longer scrolls the page. The iframe address fragment was `#sN`, and the iframe document has an element with that id, so the browser scrolled it into view in the same-origin parent too (page jump of hundreds of pixels, also when a lazy iframe enters the window after the comment panel shrinks the layout). The fragment is now `#view-sN`; the embedded instance still accepts the old `#sN`. This fixes the V-23 known defect and the flaky `N-R1` (mobile) e2e scenario; the iteration compare frames (`?embed=compare#sN`, frozen older releases) are unchanged.

## [1.0.0] - 2026-11-08

### Added

- Layers: `core`, `org` and `personal` layers described by `layer.yaml`; machine config with `layers` and `layer_rules`;
  layers are chosen by the real path of the project.
- One resolver for layer paths across all commands.
- Layer composition: merging per file and per key, skills composed from several layers, `instructions/_base.d/`
  fragments, `allow_override` for overriding core elements.
- Layer commands: `skillsync layers init|add|use|update|list|check|migrate`; `--layer id=path` on commands that accept it.
- Leak guard: `skillsync leakcheck` (content, file names, commit metadata; `--worktree`, `--staged`, `--range`, `--history`)
  and `skillsync leakguard install-hook|patterns`; local git hooks that run the check.
- Version checks: `version` and `core_min` in `layer.yaml`; `layers init` writes `core_min` from the generator version.
  A layer whose `core_min` is above the generator version is BLOCKED (`core-min-unmet`). A core version that differs
  from the generator version is a warning (`core-version-mismatch`).
- Start versions of the program layers: `version` 1.0.0, `core_min` 0.9.0.
- `skillsync --version`; the generator also runs as `python -m skillsync_workflow`. Commands that Skillsync writes into
  artifacts (VS Code task, launchers, guard hooks, `{skillsync}`) call it through the same interpreter: from a checkout
  `python <checkout>/skillsync`, from the installed package `python -P -m skillsync_workflow`.
- `layers check` reports `hook-command-missing` (FAIL) when a guard hook of a layer calls a file that no longer exists.
- `SKILLSYNC_NO_SYMLINK` accepts `1`/`true`/`yes`/`on` and `0`/`false`/`no`/`off`; any other value warns and turns copy
  mode on.
- v1.0.0 supports Linux, WSL and macOS; native Windows is planned for v1.0.1. CI on Ubuntu and macOS blocks the release; the Windows jobs do not.
- Installation as a Python package with `uv tool install` (see [README](README.md)): `pyproject.toml` (hatchling, entry point
  `skillsync`), `scripts/check_wheel.py` (wheel contents) and `scripts/check_release.py` (CHANGELOG section for the version or tag).
- CI: Python 3.11 and 3.12 matrix, `install-smoke` (wheel built, installed as a tool, run outside the checkout), `e2e` (Chrome),
  `release-check`, and `release-smoke` after a `v*` tag. Tests run against the `library/` of the checkout.
- `tests/test_skillsync_library_smoke.py`: the shipped `library/` links and passes `doctor` in both link modes.
- Delivery mode: optional manifest section `delivery` (`mode`: `pr` | `direct`, `base`), validated by `skillsync doctor`
  and returned by `skillsync route` as `delivery {mode, base, source}`.

### Changed

- The library describes both delivery modes: the agent commits after each verified plan step on a work branch; `pr` (default) starts
  `pr-run` on "GO implement" and waits for `READY`; `direct` commits locally and delivers on `CP`. `CP` in `direct` now pushes
  `work:base` (fast-forward) instead of committing in place. `READY` and `READY!` come only from the user; merge and complete PR are never
  agent actions. In `pr` parallel cards get no `PUSH SLOT` on the base branch.
- A consistency guard (`tests/test_skillsync_delivery_mode.py`) fails on pre-mode sentences such as "commit only on command" in `library/`,
  on a base instruction without `READY`/`CP!`/`CPD!`, and on any instruction that allows merging or completing a PR.

### Breaking

- None against earlier public releases; this is the first public release.
- The `library` key of the machine config is not read. Run `skillsync layers migrate` (dry-run, then `--apply`);
  see [docs/upgrading.md](docs/upgrading.md).

### Fixed

- Prototype toolbar on phones (<600 px): the hint `.anno-save` has its natural width capped at 11rem and is ellipsized, so a wider system font (e.g. DejaVu Sans)
  no longer pushes the "⋯" button into a third row (logged-out toolbar 151 px → 117 px).
- E2E V-02 reads the pre-D28b engine from `tests/fixtures/prototype/engine-v2-prev/` instead of git history, which the public core does not have;
  V-02 now checks that the bar is not taller than the reference (+2 px) instead of equal to it (D271).

### Known issues

- E2E scenario N-R1 (comment panel, mobile view) is unstable: it sometimes fails with a page jump of about −3000 px (open shift equals close shift).
  On clean `main` 6134a8c: 2 of 6 runs fail with DejaVu Sans, 0 of 6 with the default font. Possibly related to V-23. Fix planned for 1.0.1.
