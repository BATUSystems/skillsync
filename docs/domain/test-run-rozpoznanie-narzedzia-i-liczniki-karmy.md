Reguła rozpoznania: `detect_tool` zwraca narzędzie w kolejności: (1) pierwsze słowo po zdjęciu opakowań (słowa modułów, potem narzędzia z tabeli); (2) słowo po `-m`, gdy wcześniej stoi „gospodarz” (`python*`, `py`, `pypy*`, `coverage`); (3) narzędzie z tabeli w pierwszych trzech słowach; (4) słowo modułu będące też narzędziem (`pytest`, `py.test`) w dowolnym miejscu. Moduł niebędący narzędziem (`unittest`) nie pasuje w krokach 3–4. Hak `guard-tests` odtwarza kroki 1–4 w `tool_of`, ale klasyfikuje program tylko kroki 1–2 (krok 2 wymaga, by sam pierwszy wyraz był gospodarzem). `tox` jest narzędziem, nie opakowaniem. Szczegóły i przykłady: `docs/test-adapters.md`.

Reguła linii Karmy: `Executed N of M` jest licznikiem, gdy po zdjęciu ANSI tekst przed nim jest pusty albo jest etykietą przeglądarki kończącą się `): `, a po `of M` stoi koniec linii albo spacja i `(`, `SUCCESS`, `ERROR`, `DISCONNECTED` lub `FAILED`. `Executed` nie liczy pominiętych: passed = N − X, failed = X, skipped tylko z `(skipped S)`, total = M. Kilka przeglądarek: suma ostatnich linii każdej etykiety. Jedno źródło semantyki: `test_adapters/karma_line.py` (czytnik na żywo, `quality._test_counts`, `_failure_count`). Niewykonane (`total − executed − skipped > 0`, np. `Executed 3 of 11 DISCONNECTED`) nie są pominiętymi: `skipped` pochodzi tylko z nawiasu. Przy kodzie wyjścia 0 takie wyjście nie jest dowodem: `validate` i `test-run` dają `BLOCKED` („Karma executed N of M specs”); zdejmuje to `success_pattern` w `validate`, a `--allow-no-count` i `--allow-skips` w `test-run` nie.
Kody wyjścia i ślad przebiegu: PASS 0; `FAIL` (kod polecenia ≠ 0) zwraca kod polecenia; bieg z kodem polecenia 0 bez zapisanego `PASS` (zapisany `BLOCKED`: brak dodatniej liczby testów, pominięte bez zgody, „kod 0, ale wyjście raportuje niezaliczone”, niewykonane specyfikacje Karmy; albo brak zapisu statusu po błędzie zapisu lub przerwaniu) daje 2 i linię stderr `test-run: exit code 2: …`; 124 limit czasu, 127 brak programu; `--import` zwraca 0 przy poprawnym imporcie niezależnie od statusu biegu. Kod polecenia 2 jest po samym kodzie nierozróżnialny od BLOCKED 2 (także przed startem: zły argument, kilka kroków w toku); rozróżnia linia stderr `test-run: step <id> (<źródło>), attempt <n>: <STATUS>` i `BLOCKED: …`. Kod 0 zdejmują tylko `--allow-no-count` (brak liczników) i `--allow-skips`; zero wykonanych testów, „kod 0, ale wyjście raportuje niezaliczone” i niewykonane specyfikacje Karmy nie mają zdjęcia żadną flagą. Znana luka: Karma `(N FAILED)` przy kodzie polecenia 0 nie jest czytana (bieg `PASS`). Ślad przebiegu: `--run <id>` (także z `--import`) wymaga w `.skillsync/runs/` katalogu `<id>/` (nie dowiązania) albo zwykłego pliku `<id>.json`, nazwa dokładna; bez śladu BLOCKED 2, nic się nie zapisuje, polecenie nie startuje; wybór domyślny bez `--run` bierze jedyny katalog (rekord i dowiązanie się nie liczą).
